# دليل الدمج

## كيف يوصل شغلك للمتحف؟

```
فرعك  ←  Pull Request  ←  مراجعة مسؤولة الدمج  ←  main  ←  المتحف
```

لا أحد يرفع على `main` مباشرة. كل شغل يمر بمراجعة.

## أسماء الفروع

| المهمة | اسم الفرع |
|---|---|
| المهمة 1: البيئة | `env/وصف-قصير` مثل `env/lobby-lighting` |
| المهمة 2: الجنوب والشمال والشرقية | `data/south` أو `data/north` أو `data/east` |
| المهمة 3: نجد والحجاز | `data/najd` أو `data/hijaz` |
| المهمة 4: المجسمات | `models/اسم-المعلم` مثل `models/qasr-al-farid` |
| المهمة 5: غرفة الأزياء | `fashion/وصف-قصير` |
| المهمة 6: الوكيل الذكي | `agent/وصف-قصير` |

الأسماء بالإنجليزي، حروف صغيرة، وبينها شرطة `-`.

## قبل ما تفتحين Pull Request

- [ ] المشروع يشتغل عندي بـ `npm run dev` بدون أخطاء.
- [ ] عدّلت داخل مجلد مهمتي فقط.
- [ ] كل معرّفات المعالم مطابقة لملف البيانات.
- [ ] أضفت المصادر لكل معلومة.
- [ ] ما رفعت مفاتيح أو كلمات مرور.

## إضافة قاعة أو معلم بدون تعديل البيئة

البيئة مبنية بحيث كل قاعة **مكوّن مستقل**:

- كل قاعة تعرّف نفسها بالواجهة `RoomModule` في `src/types/room.ts`.
- كل قاعة فيها **أماكن جاهزة** (`LandmarkSlot`) يُربط فيها المعلم بمعرّفه.
- لما تنضاف بيانات معلم ومجسمه بنفس المعرّف، يظهر تلقائيًا في مكانه.

يعني فريق البيانات وفريق المجسمات **ما يحتاجون يلمسون كود المتحف**.

## إذا خرب شيء بعد الدمج

المجموعة المسؤولة عن المكوّن هي اللي تصلحه، ومسؤولة الدمج تساعد في التشخيص.
